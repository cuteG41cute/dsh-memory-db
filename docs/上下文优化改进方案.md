# 记忆数据库插件 · 上下文优化改进方案（汇总版）

> 状态：**待实施**（等待批准后按「十、实施步骤」落地到 memdb-4）
> 日期：2026-08-19
> 本方案汇总此前讨论的全部改进方向：按需注入分类器（是/否）、模型提炼关键词的直接关键词检索、注入预算双上限、20% 历史压缩（仅注入回合）、原文 20% + 分块摘要 20% 注入构造、前缀缓存纪律、去重复用、可观测性等。

---

## 一、目标

在「尽可能保持记忆可用」的前提下，把记忆注入对**上下文占用**与**前缀缓存命中率**的负面影响压到设计下限：

| 场景 | 期望行为 |
|---|---|
| 连续话题回合（占多数） | 注入 = 0，前缀缓存逐字节连续命中，历史完整保留 |
| 话题转向回合 | 注入 ≤ 40%（双上限锁死），历史按动态预算压缩（历史+注入 ≤ 60% 窗口），缓存仅一次性失效 |
| 任何极端情况 | 注入量不可能撑爆上下文；漏注入的概率被降到最低（宁多勿漏） |

## 二、总体机制全景

```
每回合 pre-step:
  ├─ 存在上一个用户问题？
  │    ├─ 否（会话首问）→ 分类/提炼回合（intent: recall|shift，无延续性可判）→ 注入流程
  │    └─ 是 → 分类回合（B 常驻子代理 / A 主模型隐身，一次输出 intent+task+关键词）
  │         ├─ intent="recall"（语意含回忆需求，如"我们之前…/回忆一下…"）→ 强制标准注入
  │         ├─ intent="continue"（话题延续）→ 不注入、不压缩，缓存全连续（短路，不再判断任务类型）
  │         └─ intent="shift"（话题转向 / 任何失败）
  │              ├─ task="single"（单次任务）→ 轻量注入流程
  │              └─ task="normal"（常规话题）→ 标准注入流程（用本回合产出的关键词）
  └─ 标准注入流程：
       ① 动态压缩判断：历史预算 H = 内容上限(60% × 窗口 ∩ 剩余可用) − 计划注入量；历史估算 > H → compactNow(agent)（异步，下回合生效，仅注入回合触发）
       ② harness 用关键词直接匹配检索 → 全量命中结果按时间近→远排序（不裁剪）
       ③ 统一估算器估算总量 → 总量判断：≤ 注入上限 → 全量原文注入（跳过压缩）；> 上限 → 预算化
       ④ 超限时构造注入块：原文段(近→远填 20% 窗口) + 子代理分块摘要(20% 窗口)，合并为一份「记忆资料」
       ⑤ 去重复用（与日志最后一条注入块逐字节相同则跳过）
       ⑥ 尾部追加注入消息（字节一致重放），等待模型回答

  轻量注入流程（单次任务）：
       ① 动态压缩判断：H = 内容上限(60%) − 注入量(≤5%)；历史 > H → compactNow（异步）
       ② harness 用关键词直接匹配检索 → 全量命中结果按时间近→远排序（与标准模式相同）
       ③ 原文填充至 min(5% × 窗口, 可用)，超出的老消息直接截断丢弃（不压缩、不调子代理）
       ④ 去重复用 + 尾部追加，等待模型回答
```

## 三、分类器：按需注入判定（是/否）

### 3.1 触发与输入
- **触发条件**：会话中已存在上一个用户提问。参照消息 = 会话日志**最后一条 `source.kind === 'user'`**（注入消息、系统消息不计入）。
- **输入**：最近 K 轮问答 + 当前问题。K 默认 5，可配置 3~5（B 为子代理自身上下文滚动；A 为完整前缀）。
- **输出**：`{"intent":"recall|continue|shift","task":"single|normal","keywords":[...]}`；`reasoningEffort` 置 `off`（DeepSeek 等适配器支持；A 路径依赖该能力，不支持的适配器在 A 失败后直接走兜底）。
- **判定语义（按优先级短路，先判回忆、再判延续、最后判任务类型）**：
  1. `intent="recall"` = 用户语意含**回忆需求** → **强制标准注入**，不做后续判断。判定为**语义级**而非关键词匹配（见 3.5）：
     - 显式引用过往："我们之前…""上次你说过…""之前我跟你说过…""你记不记得…""回忆一下…"（示例，非穷举）
     - 隐式依赖过往：问题引用了此前讨论过的概念/决定/数据/人名且未重新交代上下文；含"上次/之前/曾经/当时"等时间回溯语义
     - 结合最近 K 轮上下文判断"该问题是否必须借助过去信息才能回答"
  2. `intent="continue"` = 话题延续 → **不注入，短路**（不再判断任务类型、不提炼关键词）；
  3. `intent="shift"` = 话题转向 → 继续判断任务类型：`task="normal"` → 标准注入（40% 预算 + 关键词检索）；`task="single"` → 轻量注入（5% 预算、原文截断，见 5.4）。

### 3.2 分级实现（B 主用，A 备选/降级）
- **B（主用）——常驻分类子代理（免额外 API）**：利用 harness `ctx.subagents` 的**可续接子代理**（`startContinuable` + `followup`，持久化、进程重启后冷恢复）为会话挂起一个常驻"话题分类"子代理：
  - 每轮用户提问时，插件向其 `followup` 发送「最近 K 轮问答 + 当前问题」；子代理回合一次输出 `{"intent":"recall|continue|shift","task":"single|normal","keywords":[...]}`
  - 子代理自身上下文即滚动窗口（天然短小），与主会话完全隔离，不污染主对话缓存；无需用户提供第二个 API
  - 子代理忙碌中（上一回合未完成）→ 本轮降级 A，避免排队延迟
- **A（备选/降级，零配置）**：主模型隐形调用。输入 = 系统提示 + 会话历史 + 当前问题（即回答调用的完整前缀），输出"是/否"（+ 关键词），`reasoningEffort: off`。
  - 启用时机：子代理服务不可用 / B 调用失败或超时 / 子代理忙碌 / 用户显式配置优先走 A。
  - 附赠优势：判断调用等于给回答调用**预热前缀缓存**。
- **兜底**：A、B 均失败 / 超时 / 输出无法解析 → 一律按**"否"**处理（注入）。宁可多注入一次，不可漏注入。

### 3.3 纪律
1. **分类调用隐身**：裸 `llm.stream()` 发起，**不写会话日志、不进入主对话序列**——否则分类器自身会污染主对话缓存。
2. agent 侧保留 `memory_search` 工具，作为**第二道防线**（即使漏判，模型仍可主动按需检索）。
3. 判定"是"的回合：注入 = 0，历史不压缩，前缀缓存逐字节连续命中。

### 3.4 关键词提炼（与分类判定合并为一次调用）
- **触发**：分类回合输出后按其分支使用；**会话首问**（无上一个问题）也走同一回合（无延续性可判，只输出 `recall` 或 `shift`+`task`）。
- **调用**：与分类判定**合并**——B（常驻子代理）或 A（主模型隐身调用）在同一次回合中输出：
  - `{"intent": "recall|continue|shift", "task": "single|normal", "keywords": ["...", ...]}`
  - `intent="continue"` → 不注入、不检索（keywords 为空，短路）
  - `intent="recall"`（回忆需求）→ **强制**标准注入，用 `keywords` 检索（3~10 个）
  - `intent="shift"` + `task="normal"` → 标准注入，用 `keywords` 检索（3~10 个）
  - `intent="shift"` + `task="single"`（单次任务）→ 同样用 `keywords` 检索，但按轻量路径注入（5% 预算、原文截断，见 5.4）
- **输入**：最近 K 轮问答 + 当前问题（B）；或系统提示 + 会话历史 + 当前问题（A）。
- **失败兜底**：调用失败/超时/解析失败 → 按"否"+normal 处理：将提问原文按既有分词规则切词作为关键词，继续标准注入（流程不中断，宁多勿漏）。

### 3.5 分类器提示词设计（语义级判定）
分类回合的系统提示按以下规则编写，**recall 判定是语义理解而非关键词检测**：
- **判断依据**：
  1. **回忆需求**：用户是否在引用、询问或依赖**过往对话信息**。显式短语仅作示例（"我们之前…""上次你说过…""之前我跟你说过…""你记不记得…""回忆一下…"）；更常见的是**隐式**——问题引用了此前讨论过的概念/决定/数据/人名且未重新解释，或含"上次/之前/曾经/当时"等时间回溯语义；
  2. **延续性**：当前问题是否在推进上一轮话题（同主题追问/补充/修正）；
  3. **任务类型**：转向后的问题是单次任务（如"今天天气如何？"）还是常规话题。
- **判定顺序**：先判回忆（有 → recall，短路）→ 再判延续（延续 → continue，短路）→ 最后判任务类型。
- **偏置**：不确定时**倾向 recall**（强制注入的成本远低于漏注入，宁多勿漏）。
- **输出**：仅 JSON `{"intent":"recall|continue|shift","task":"single|normal","keywords":[...]}`；`keywords` 仅注入分支需要（3~10 个），continue 分支为空。

## 四、注入预算：双上限

```
内容预算 C    = min(60% × contextWindow, 剩余可用)        ← 历史对话 + 注入记忆 合计上限
可用          = contextWindow − 已用估计 − maxTokens(输出预留) − 安全余量(默认 10~15%)
标准模式注入上限 = min(40% × contextWindow, 可用)
轻量模式注入上限 = min(5%  × contextWindow, 可用)   ← 单次任务，标准模式的 1/8
历史预算 H    = C − 计划注入量 M                        ← 动态：记忆多则历史少，记忆少则历史多
```

- **contextWindow 解析阶梯**：`llm.resolveModelInfo(provider, model).context?.contextWindow ?? 插件配置 defaultContextWindow ?? 32768`。宁可低估、不可高估（低估只是少注入，高估会撑爆）。
- **内容预算 60%**：注入回合保持「注入记忆 + 历史对话」合计 ≤ 60% × 窗口（与剩余可用双约束）。数据库命中少时注入量小，历史可保留更多保证体验；命中多时历史让位给记忆。
- **已用估计**：统一估算器 ×（系统提示保守值 + 当前会话消息）。
- **maxTokens**：取 agent 输出预留配置或模型 `defaultMaxTokens`，保守默认 2048。

### 统一估算器
- CJK：约 1 字 ≈ 1 token；ASCII：约 4 字符 ≈ 1 token；一律向上取整、保守取值。
- 填充 20% 与压缩目标 20% 必须使用**同一个估算器**，避免原文段实际超限。

## 五、注入内容构造（关键词检索 + 全量 / 原文 + 摘要）

### 5.0 检索机制（替代原模糊搜索）
- **检索词来源改为模型提炼的关键词**，不再由插件拿提问原文做二元组模糊打分：
  1. 分类器判定需注入后，插件隐身调用模型从当前提问提炼 3~10 个关键词（见 3.4）
  2. harness 拿关键词在数据库中做**直接子串匹配**（忽略大小写）：问题或回答命中任一关键词即入选，**命中即全量提取、不做条数裁剪**
  3. 入选结果**按时间由近至远排序**（不按相关度排序：能命中的都是相关记忆，近因优先保真）
  4. `memory_search` 工具同步改用同一套关键词匹配与排序（模型自选关键词直接搜索），与注入引擎一致
- **注入消息明确告知关键词来源**，模板（变更点：开头标注）：

```
【历史记忆参考 · 项目记忆库】以下是根据你提炼的关键词「记忆数据库、上下文、缓存」
从项目记忆库中检索到的相关记忆资料，请结合这些记忆作答：

[1] 时间: 2026-08-19 15:07
会话: …（该会话标题变更历史: …）
问: …
答: …

请以以上记忆资料为参考判断用户意图，再回答用户当前的问题；若记忆与当前问题无关则忽略。
```

### 5.1 总量判断与全量注入（保留）
用统一估算器估算检索结果总量，先判断再决定是否压缩：
- **总量 ≤ 注入上限**（= `min(40% × contextWindow, 可用)`）→ 全部以**原文形式**注入（按时间近→远排列），形成完整「记忆资料」，**不执行任何压缩程序**——省一次子代理调用、保住缓存；
- **总量 > 注入上限** → 进入 5.2 的「原文段 + 摘要段」流程。

### 5.2 原文段 + 摘要段（超限时）
- **原文段**：按时间近→远，**从最近的开始写入，填满 `20% × contextWindow`**（受注入双上限约束），近因记忆原文保真。
- **摘要段**：剩余内容（更早的记忆）按「子代理窗口 × 50%」**分块** → 每块单独压成摘要 → 合并各块摘要（仍超目标则二级压缩）→ **收敛到 `20% × contextWindow`**（受注入双上限约束）。
- **合并注入**：原文段在前、摘要段在后，**合并为一份完整的「记忆资料」**注入，并标注压缩覆盖范围与时间跨度。
- **失败降级**：摘要生成失败/超时 → 仅注入原文段（宁少勿错），下个注入回合重试。

### 5.3 去重复用
命中结果与日志**最后一条注入块逐字节相同** → 不追加、直接复用（连续同话题追问时新增注入 = 0）。

### 5.4 轻量注入（单次任务模式）
分类回合判定 `task="single"`（如"今天天气如何？"这类一次性请求）时：
- **检索与标准模式一致**：同样用分类回合产出的关键词做直接子串匹配，全量命中按时间近→远排序——注入的是**相关记忆**而非固定最近的几条，避免每次单次任务重复注入相同内容
- **预算**：`min(5% × contextWindow, 可用)`——标准模式 40% 的 1/8
- **构造**：命中结果**原文填充**至预算上限，超出的老消息**直接截断丢弃**（不做子代理压缩，零额外成本、零延迟）
- **目的**：单次任务不需要完整背景，但少量相关记忆（用户偏好/项目上下文）不降低体验
- **去重与尾部注入纪律不变**（与 5.3、七节相同）

## 六、历史压缩（动态预算，仅注入回合）

### 6.1 触发条件（动态，不固定 20%）
注入回合 pre-step：估算当前历史（含累积的旧注入块），与**动态历史预算**比较：
- 历史预算 `H = min(60% × contextWindow, 剩余可用) − 计划注入量 M`
- 历史估算 > H → `ctx.compaction.compactNow(agent, signal)`（异步，下回合生效）
- **动态性**：记忆命中多 → M 大 → H 小 → 历史压缩狠、给记忆让位；记忆命中少（如轻量注入 5%）→ M 小 → H 大 → 历史几乎不动，保留完整对话保证体验
- **连续对话回合不主动压缩**，历史完整保留、缓存零中断，仅依赖 harness 原生压力阈值防爆
- 压缩会把**累积的旧注入块一并回收**进摘要，上下文收敛、不会无限膨胀

### 6.2 harness 契约（已核实）
- `compactNow(agent, signal)` 是手动强制压缩；Agent 对象本身满足 `ManualCompactAgentContext`，直接传入。
- 经 `runMaintenance` 在 **idle 阶段异步执行**：当前回合不受影响，**下回合生效**。
- `compaction/start → end` 持久锁防并发；`busy` 等失败分类错误 → 捕获降级、**下个注入回合重试**。
- 压缩后摘要大小由 harness 实现决定；若极端情况下压缩后仍超历史预算 H，下回合再次触发收敛。

## 七、前缀缓存纪律

1. **注入永远追加在消息尾部**，绝不修改系统提示或历史中段（中段改动会杀死其后全部缓存）。
2. 注入消息以 `user/message` 记录一次，此后**重放字节一致**（与 dsh-time-stamp 同模式，缓存友好）。
3. **确定性渲染**：同一检索结果集 → 同一字节流。
4. **去重复用**（见 5.3）：同话题连问时注入 = 0。
5. **压缩是唯一的前缀缓存一次性失效点**，且与注入时机同频（仅注入回合）。
6. **分类器与关键词提炼均不进主会话日志**：B 走常驻子代理的独立会话（与主对话完全隔离），A 走裸 `llm.stream`；只有最终注入消息会落入主会话日志。

### 预期收益（128K 窗口示例）
| 指标 | 现状（每回合强制注入） | 本方案 |
|---|---|---|
| 连续话题回合（约 60~70%） | 每回合注入 ≤40% | 注入 0，缓存全命中 |
| 转向回合（约 30~40%） | — | 注入 ≤40% + 一次压缩 |
| 平均每回合未命中 prefill | 40% + 对话增量 | ≈15% + 对话增量 |
| 压缩频率 | 每 1~2 回合 | 仅转向回合 |
| 代价 | — | 每回合一次"是/否"分类调用（B：短滚动上下文、便宜模型；未配置时降级 A：输入命中缓存、输出 1 token、思考 off） |

## 八、可观测性：memory_admin status

`memory_admin status` 扩展展示：
- **生效窗口**：实际解析到的 contextWindow（含解析阶梯来源）
- **注入预算**：40% × 窗口 与 剩余可用 双上限的实际数值
- **分类策略**：当前生效路径（B / A / 兜底）与每回合判定结果分布（是/否/失败）
- **压缩状态**：最近一次 compactNow 的时间 / 结果 / 重试次数
- **统计**：注入次数、去重命中次数、预算占用
